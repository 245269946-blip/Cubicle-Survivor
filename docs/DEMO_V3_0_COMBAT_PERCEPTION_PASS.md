# 《工位幸存者》Demo V3.0 战斗感知与霓虹表现说明

状态：已实现并进入回归验证  
入口：`Cubicle-Survivor-demo/demo-v3-0.html`  
前序快照：Demo V2.9 继续保留，不被覆盖。

## 一、本轮目标

Demo V3.0 是建立在 Demo V2.9 四武器固定框架上的第一轮战斗体验优化。

本轮只解决一个问题：

> 已经存在的机制，是否能被玩家在战斗中看见、理解，并感到自己的选择已经生效。

不新增道具系统、不扩展武器池、不增加新的敌人系统宽度，也不改写 5 阶段 17 关、模块、经验与组件的职责边界。

## 二、第一性原理

每把武器都必须形成可见的因果链：

> 行为 → 状态 → 结果

- 马克笔：划出路径 → 路径复写或留档 → 队列被切割或战场被墨迹覆盖。
- 保温杯：近距喷汽 → 冷凝或聚焦 → 空间被控制或击杀转成热浪。
- 剪刀：判断移动方向 → 轻步进场并完成剪切 → 以裁断、终幕或处决收束动作轮。
- 修正液：锁定目标并喷涂 → 错误层数增长 → 污染扩散或最终纠错。

任何升级如果只有数字变化、没有画面或行为变化，就不能单独承担主要成长反馈。

## 三、战斗反馈改动

### 1. 通用命中语法

- 敌人受击时产生短促形变与武器家族色闪光。
- 高威胁远程敌人在发射前出现可读预警。
- 四把武器各自使用已登记的击杀确认事件，不共用无来源的通用特效。
- 所有新增反馈源继续注册在 `src/v2/data/form-signatures.js`，视觉与音频事件表保持一一对应。

### 2. 修正液基础状态

- 喷射前先显示目标锁定。
- 1—3 层错误标记按层数增加尺寸、亮度和故障程度。
- 错误区域生成时提供一次感染脉冲，区域持续表现仍由真实判定对象驱动。
- 错误锁定、感染、过载、区域、崩溃和纠错继续保持不同事件职责。

### 3. 成长确认

经验属性、模块和组件完成选择后，回到战斗会显示一次短促确认：

- 本次改变属于属性、工作流还是组件；
- 具体名称；
- 下一轮攻击会发生什么变化。

提示是短时、浅层且偏离玩家中心的，不新增常驻说明条。

## 四、数值边界

- 剪刀基础伤害从 28 降至 25。
- 剪刀裁断倍率从 1.85 降至 1.70。
- 提高群消息轰炸、截止日期冲锋、客户追问等带预警攻击的伤害。
- 提高敌方射弹结算系数，但不提高无预警的普通贴身碰撞伤害。

目的不是单纯提高难度，而是让剪刀必须承担贴身风险，让玩家通过看见并处理危险获得生存空间。

## 五、日本霓虹都市视觉语言

本轮不把所有元素统一染亮，而是规定颜色职责：

- 青色：路径、信息、锁定和系统连线。
- 品红：错误、异化、故障与危险。
- 金色：成长、奖励、结算和完成确认。

应用范围包括：首页、武器选择、关卡预告、战斗 HUD、Build 状态、经验属性页、模块页、组件商店、暂停与结算页。UI 外框保持暗色办公室结构，霓虹只承担信息层和焦点层。

## 六、玩家可视内容检查表

每次发布必须按下列顺序检查：

1. 首页版本号、说明和主按钮是否属于当前版本。
2. 武器选择页四把武器是否完整可见，母题和描述是否不溢出。
3. 1280×720 战斗页是否保留中心移动与瞄准空间。
4. 关卡预告是否说明真实敌人和真实通关条件。
5. 命中、敌人攻击预警、击杀、受伤是否都有可区分反馈。
6. 经验、模块、组件页是否完整显示选择前后变化。
7. 回到战斗后是否出现短促的成长确认，且不会遮挡玩家。
8. 修正液 0—3 层错误、过载和污染区域是否一眼可辨。
9. 剪刀完整模型、张刃方向、轻步方向和动作终结是否一致。
10. 结束后重新开始是否恢复四武器选择。

## 七、验收结果

自动验证覆盖：

- Demo V2.9 快照仍存在；
- Demo V3.0 独立入口与协调器身份；
- 四武器命中、锁定和击杀事件进入视觉/音频契约；
- 成长选择会排队生成玩家可视确认；
- 剪刀伤害回调但完整模型不回退；
- 既有 17 关、24 种组件属性变体、68 个武器/关卡切换和双路线实战浸泡继续通过。

浏览器验证使用 1280×720 视口，检查首页、四武器选择、修正液开局、模块选择、组件商店和属性升级页的可见内容与溢出。
