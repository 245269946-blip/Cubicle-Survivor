# Visual QA Checklist

每次提交前必须做一次视觉检查，尤其是中文 UI 和贴图。

## 必查项

- 中文标题、标签、按钮必须横向显示，不能逐字竖排。
- 卡片内图标、标题、标签、描述不能互相遮挡。
- 弹层打开时，关卡横幅、提示条、暂停按钮不能盖在弹层内容上。
- 桌面 16:9 视口检查升级面板、工坊面板、结算面板。
- 移动窄屏视口检查升级面板和结算面板，内容不能横向溢出；必要时允许纵向滚动。
- 贴图和图标必须落在自己的容器内，不能漂到文字上或被裁掉关键部分。
- 按钮文字必须完整可读，不能被压缩到单字换行。

## 生成资产进入实机门禁

先分类，再接入；“代码里能画出来”不等于“可直接用于游戏”。

1. 生成前声明资产等级：`reference-only`（概念参考）、`prototype-cutout`（可用于 P0 的单张剪影）或 `runtime-ready`（正式实机资产）。
2. 生成前写清运行角色、目标绘制尺寸、镜头/透视、所需方向、动画帧、锚点、透明背景与安全留白；缺一项不得按正式资产出图。
3. 文件检查必须确认真实 alpha、四角透明、无棋盘格和白边；角色/敌人的去透明包围盒原则上覆盖画布至少 80%，除非清单登记了特效或动作留白理由。
4. 运行时不得把非同宽高比源图直接压进目标框；裁切后仍要保留脚底、枪口、命中部位和预警轮廓。
5. 必须在实际战场背景、真实目标像素尺寸下合成检查，而不是只看生成大图或透明图查看器。
6. 人物与瞄准武器必须覆盖实际方向，或能由运行时安全连续旋转；视觉枪口、攻击起点、攻击方向和判定必须一致。
7. 至少截取静止、移动、攻击、受击和完成/消失五种状态。只有全部通过，清单与报告才能写 `runtime-ready`。
8. P0 可以使用 `prototype-cutout`，但必须在资产清单和交付说明中列出未通过项；不得用“已实装”偷换成“正式可用”。
9. 色键去底不能只信自动取样或肉眼透明预览：必须抽查肤色、白衣、黑发和装备像素的 alpha；键色通道被错误识别时会把人物内部挖空。
10. 去底后必须分别在浅色战场背景和透明查看器检查紫边/白边，再以真实 132px、78px 尺寸合成；大图正常不代表缩小后可用。
11. 生图给出的多姿态横条只能登记为源图，不能默认按画布等宽切格；肢体、纸角或装备跨过名义分隔线时，必须按真实 alpha 连通域拆姿态，再统一可见高度、脚底线、身体中心与安全留白。
12. 帧动画必须逐帧固定检查并再做一次正常时序实战。人物至少验证每个方向的 `idle / step-a / step-b`，敌人至少验证动作的预备、执行与回收；所有帧画面指纹不同才证明不是重复帧或单图抖动。
13. 生成目录不是项目依赖。源图、透明中间图、正式图集、构建脚本、帧合同和运行报告都必须保存在项目内，并用 hash 绑定关键运行时文件；只留下概念图链接不得报告为可复用资产。
14. 生图服务不可用、额度不足或结果未达到既定视觉标准时，正式素材批次状态必须写为“阻塞/未完成”。本项目不得用线稿 SVG、Canvas 几何、概念图或其他占位素材降级顶替后仍标记 `runtime-ready`；恢复生产后必须重新走源图、真实 alpha、目标尺寸合成、逐帧实战和回归隔离门禁。

## 当前推荐验收视口

- Desktop: 1600 x 900
- P0 target: 1280 x 720
- Mobile: 390 x 844
