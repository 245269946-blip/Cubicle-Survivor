# Demo V3.15 正式版卡通素材生产

状态：正式发布。Demo V3.15 继承 Demo V3.14 的四武器、17 关、成长、经济与轻量决策合同；敌人、Boss、场景、掉落物、HUD、四武器特效与正式音频均已通过独立门禁，Demo V3.14 保持可回归。

入口：`Cubicle-Survivor-demo/demo-v3-15.html`

## 第一性原则

正式版不是把 P0 大图缩小后全部覆盖，而是让每个战斗对象都形成同一条可验证因果链：

`身份轮廓 → 移动方式 → 动作预备 → 判定时刻 → 受击 → 退场 → 任务结果`

每批素材必须同时完成：

1. 与共享员工角色一致的粗轮廓、暖纸色办公室卡通语言；
2. 真实低帧动作，不用整张贴图漂移、旋转或缩放冒充动画；
3. 左右朝向或所需四方向覆盖；
4. 生成源、透明中间图、正式图集、构建脚本、帧合同和 manifest 全部留在项目；
5. 目标战斗尺寸逐帧检查，动作命中帧与真实判定同源；
6. 独立版本实战通过后才标记 `runtime-ready`，不允许未完成批次污染 V3.14。

## 正式四武器特效

- 马克笔、保温杯和修正液继续使用 v2 图集，剪刀使用 `scissors-vfx-v3.png`；全部均为 1024×512、4 列 × 2 行透明 PNG 位图。列顺序固定为预备、释放、命中、消退，第一行表达基础动作，第二行表达路线或结算动作。
- 八种运行时身份分别是划线 / 归档、蒸汽扇面 / 击杀热浪、闭合突刺 / 张刃剪切、修正喷涂 / 错误崩溃。粗深棕轮廓、奶油纸色、低饱和蓝、琥珀和珊瑚色替代旧霓虹、像素与高细节金属混搭。
- 当前正式图集来自项目内留存的生图色键源，经确定性脚本去底为真实 alpha、按每格可见包围盒归一化后进入运行时；旧线稿 SVG 仅保留历史追溯，不在正式注册表中加载。若后续再次遇到额度或服务限制，本批次必须回到“阻塞/未完成”，不得恢复线稿兜底并宣称正式完成。
- 剪刀 v3 恢复 V3.9 已验证的“同一把完整剪刀”因果：八帧全部保留两枚手柄环、中央铰链和两片完整刀刃，合刃以闭合突刺为主体，张刃以真实开合和青/品红丝线为主体；纸片、月牙和爆点只能做辅助，不能替代剪刀。当前生图源、真实 alpha 图和正式图集均已保存，`npm test` 全量逻辑回归通过；由于本地页面被浏览器 URL 安全策略拦截，新图尚未重新采集 1280×720 实机证据，因此不得沿用旧 v2 截图把剪刀 v3 标为 `runtime-ready`。

## 生成资产准入与界面记忆

- 生图首先是生产源，不是成品。只有透明裁切、帧格几何、目标尺寸、方向覆盖、运行时接线、真实判定共源和浏览器证据全部通过，才允许标记 `runtime-ready`；单纯概念图、展示大图或“代码能加载”均不计完成。
- 图集首次进入页面需要完成解码、切片与重绘。自动截图至少等待 4.2 秒并确认 HUD、玩家与目标对象同时可见；首帧只见背景或单个精灵不能作为失败或通过证据。
- 玩家必须保持同一共享身体与身份，四种武器、四方向、步态、成长路线和动作状态一起过矩阵；武器只通过前后穿戴层和真实瞄准实体表达差异。
- 购买、模块与选择页面继续执行 V3.14 的极简合同：名字 + 立即结果 + 最多一条未来/关系提示。不能为了讲清系统重新堆回大段文字；策略要从可见差异和即时反馈中读出。

### 2026-08-27 GitHub Pages 加载加固

- 问题不是线上文件 404：对 135 个运行时图片/音频引用的线上检查均为 `200`、MIME 正确且长度非零。真实风险是首屏同时请求约 75 MB 全量素材，国内访问 GitHub Pages 时会产生随机超时，且旧加载器没有失败反馈。
- V3.15 现在只把首关必需的场景、共享角色、四武器穿戴层、首批敌人动作、四套武器特效、三类掉落物与血条共 22 项设为开局门禁；最大并发为 6，单项 18 秒超时，失败最多重试 4 次。
- 22 项完成前开始按钮保持禁用并显示真实进度；最终失败时提供“重试画面素材”。门禁完成后才低优先级预取正式版后续阶段素材，旧回归版本素材只在实际使用时加载。
- 选择页删除流程条、卡片长描述和底部重复提示，只保留武器图、名称与一个攻击标签；组件商店删除流程条、实体安装说明和重复规则，只保留可立即做决定的信息。
- 以后线上素材验收必须同时覆盖“文件存在”和“受限网络下的请求策略”。只做 200/文件存在检查不能证明玩家端不会出现随机空图。
