# 《工位幸存者》武器视觉与战斗因果设计规范

状态：全项目可复用硬规范。新武器、模块、组件、融合效果和既有武器视觉返工均适用。

## 0. 跨武器人物一致性硬门槛

- 同一个可玩角色在所有武器中必须保持同一身份、头身比、发型、服装、四方向朝向、战斗高度和像素密度。
- 新武器视觉应以当前已实装角色图集为比例参考，不得重新解释人物；选择武器只能改变穿戴异化层、武器实体和攻击反馈。
- 人物完整图集若无法与既有角色逐格对齐，应改为“稳定人物骨架 + 穿戴层 + 武器层”，不得用画风不同的整张人物插画替换。
- 大型武器和路线装置可以越出人物包围盒，但不得长期遮挡头部、躯干朝向和脚步，也不得使人物在实机中看起来突然变高、变瘦或变成另一种画风。
- 任何新人物/穿戴资产进入实机前，必须与至少两把已实装武器在同一目标战斗尺度下并排截图；比例或身份不一致即退回。当前固定四武器目标是图集绘制高度 78px、人物透明像素可见高度约 55—59px，接近旧版 70px 图块中的真实人物占比。
- 禁止只比较素材外框高度。人物、武器和装置必须按去透明边后的真实像素包围盒测量；“锚点在外围”但长轴素材穿回人物主体，仍视为遮挡失败。
- 普通敌人的基础可见尺寸约 48px。玩家人物不含武器的可见高度应控制在普通敌人的约 1.15—1.3 倍，不得因为更换武器突然变成 1.7 倍以上。

## 1. 第一性原理

玩家看到的武器不是角色旁边的一组图标，而是一套正在工作的战斗装置。每个可见部分必须同时回答五个问题：

1. 它属于谁？
2. 它安装在哪里？
3. 它跟随人物朝向、攻击瞄准还是世界坐标？
4. 它怎样参与“动作 → 状态 → 结果”的因果链？
5. 它的画面位置是否与真实判定一致？

任何答不出的部件都属于“孤立道具”，不得直接进入实机。

最终目标不是把装备堆在角色周围，而是让普通办公用品在压力中逐步长成荒诞、可读、可操作的职场异化身体。

## 2. 统一视觉母题

### 2.1 风格公式

> 荒诞现实办公用品 + 赛博霓虹都市光感 + 清楚的游戏尺度结构

- 办公用品必须保留一眼可认的现实原型：马克笔、墨仓、保温杯、剪刀、修正液瓶等。
- 异化可以夸张，不要求严谨工业结构，但必须遵守自身建立的安装与运动逻辑。
- 霓虹用于说明能量、状态、路线和触发阶段，不能用全局染色代替形态设计。
- 避免写实硬科幻、普通桌面素材堆叠、平面图标漂浮、传统奇幻法术和不透明大光团。
- 使用“低透明外辉光 + 高对比实体核心”：先看清实体和技能轮廓，再感受光。

### 2.2 成长必须同时改变三件事

每次重要成长都必须具备：

1. **机制变化**：新增攻击事件、实体、传播、区域或结算方式。
2. **表现变化**：轮廓、数量、面积、运动或状态层级在战斗中可见。
3. **因果变化**：玩家能看懂新部件为什么产生新结果。

属性数字可以增强强度，但不能承担模块升级的主要可视反馈。重要 Build 选择必须在随后 10 秒内被玩家看到。

## 3. 可见实体的所有权分类

所有武器视觉对象只能属于以下五类之一：

| 类型 | 所有者 | 典型例子 | 跟随规则 |
|---|---|---|---|
| 人物穿戴件 | player | 背包、肩部控制器、腰部墨仓 | 人物位置与人物朝向 |
| 人物相对悬浮件 | player | 有明确悬浮设定的无人机、浮游笔架 | 人物位置；只在设定允许时有独立悬浮运动 |
| 武器安装件 | weapon | 笔头、笔身、笔尾、剪刀刃部 | 对应真实武器实体与武器朝向 |
| 世界部署件 | world | 冷凝区、即时贴节点、错误区域 | 世界坐标与自身生命周期 |
| 瞬时攻击件 | attack | 激光、剪切弧、热浪、纠错爆发 | 对应真实攻击事件与判定时间线 |

“固定”不等于只写死一个屏幕偏移。人物穿戴件必须使用人物朝向下的背部、肩部、腰部或头顶挂点；武器安装件必须读取实际武器实体；世界部署件不能跟着人物漂移。

## 4. 安装逻辑

### 4.1 人物穿戴件

- 必须明确 `socket`：背部、左/右肩、腰部、头顶、手臂等。
- 必须与身体有接触、遮挡、绑带、软管、底座或共同轮廓中的至少一种关系。
- 位于人物后方时允许被身体部分遮挡；不得长期完全消失。
- 同类路线模块应共享一套安装语法。例如马克笔先安装一个随人物朝向转动的背部打印坞：纯路线中置一枚路线墨盒，混合路线在同一坞体上左右并列两枚墨盒，禁止把两个路线件分别吊在空气中。
- 模块升级应让穿戴轮廓逐级增大、增加接口、液位/输出栅格或强化能量结构。Lv1—Lv4 的亮度必须逐级可辨，但发光只能强调真实结构，不能代替结构成长。

### 4.2 悬浮件

- 只有设定上确实是浮游设备时才能悬浮。
- 必须有稳定的相对锚点、轻微悬浮规律，以及和人物/武器可读的供能或控制关系。
- 不得把无法决定安装位置的部件默认做成悬浮图标。

### 4.3 武器安装件

- 笔头组件装在实际笔尖，笔身组件装在实际笔身，笔尾组件装在实际笔尾。
- 数量成长必须产生真实的新增发射器，不能额外漂一块“数量组件”图标。
- 组件尺寸应在游戏尺度下清楚可见，但不能比它所依附的主体更像独立武器。
- 组件状态与属性面板使用同一份数据，禁止画面显示已安装但判定未生效，或判定生效但模型没有变化。

## 5. 坐标、朝向与层级

必须分离四套坐标语义：

- `player-facing`：人物移动/站立朝向，驱动肩背、腰部和穿戴件。
- `attack-aim`：当前攻击目标方向，只驱动需要瞄准的武器或攻击前摇。
- `weapon-local`：笔头、笔身、刃部等相对武器的局部挂点。
- `world`：留场区域、陷阱、节点和敌人状态。

只有真正负责瞄准的部件才追随 `attack-aim`。墨仓、控制器、背包等不得因目标切换而围着人物旋转。

角色、武器和穿戴件使用世界 `y` 值或等价深度逻辑排序：后方设备可被身体遮住一部分，前方武器必须能被看到。不得用“所有武器永远压在人物底层”或“所有部件永远盖住人物”的固定层级。

## 6. 攻击起点与判定一致性

### 6.1 统一因果链

每次攻击都必须能沿画面追溯：

> 人物/供能装置 → 实际武器 → 技能形态 → 命中区域 → 敌人反馈

特效来源、武器朝向、碰撞几何和命中反馈必须读取同一个攻击事件对象。

### 6.2 身体—武器—外部路径

当武器幻想是“从人物发出并经过外围武器向外攻击”时：

- 判定线从人物身体开始；
- 射线经过对应武器和笔尖；
- 再延伸至攻击范围终点；
- 人物与武器之间不得形成近身伤害盲区；
- 主可见光束/墨迹从真实武器出口向外，并与外部判定共享同一路径。身体到武器出口的内部保护段可以隐藏在人物和装置轮廓下，用于消除非设计性贴身盲区；不得为了表现内部段再画第二条同向技能，造成玩家误判哪条才有伤害。

如果武器设定明确是独立无人机，攻击才允许从无人机自身开始；此时需要在设计中明确近身盲区是风险，而不是实现遗漏。

### 6.3 形状匹配

- 激光的亮核、外辉光、碰撞宽度必须同轴。
- 墨迹可以边缘柔软、不规则，但实际伤害和减速范围不得明显窄于或宽于可见覆盖。
- 剪刀的刃口、刺击尖端和剪切弧必须对齐判定发生位置。
- 蒸汽、热浪、错误区域和终局爆发都必须使用真实事件的方向、半径和生命周期。

## 7. 角色可读性与异化程度

- 角色始终保留头部、主体朝向或步态中的至少两个稳定识别点。
- 允许穿戴件与身体发生有限重叠，因为完全分离会像围绕角色摆图标；重叠必须表达穿戴关系，不能把角色整块盖住。
- 武器应尽量靠近人物，形成一个紧凑战斗轮廓；升级通过新增实体和肩背结构向外生长，而不是开局就把部件推到远距离轨道。
- “靠近”不等于与人物重叠。瞄准武器的内缘必须退出头部、胸腹和腿部构成的身体核心包围盒；只有把手、绑带、软管或穿戴接口允许与身体发生有限接触。
- 不重画每个阶段完整人物时，优先使用“稳定人物骨架 + 穿戴模块 + 实际武器 + 攻击特效”的可组合结构。
- 素材必须覆盖实际需要的朝向。单角度 3D 物件直接贴在多方向人物旁边，不视为完成。

## 8. 颜色与状态语法

颜色必须表达机制状态，而不是单纯装饰。

马克笔实验的当前语法：

| 颜色 | 含义 |
|---|---|
| 中性白 | 尚未偏向路线的基础马克笔 |
| 暖黄 | 当前发生的复写即时激光 |
| 冷青 | 留在战场上的留档墨迹与供墨系统 |
| 白色高亮 | 当前线与历史墨迹发生真实交点 |
| 洋红脉冲 | 调阅沿旧档案移动时的短暂反馈 |

其他武器应建立自己的状态表，但遵守同一原则：基础状态中性、路线色分离、融合色只在真实交互发生时出现、Lv4 拥有独立于普通膨胀的终局信号。禁止把两条路线长期混成一种高亮颜色。

## 9. 等级与轮廓

- Lv1：第一次改变动作或新增实体，玩家立刻理解路线。
- Lv2：扩大同一核心机制的覆盖或并行数量，并改变实体轮廓。
- Lv3：形成可持续循环或多阶段攻击，角色周围的装备结构明显成型。
- Lv4：改变战场治理方式；不能只是继续增加倍率或数量。
- 定向武器的 Lv4 终局仍应保留主攻击方向。若加入全屏或四散效果，主要伤害/视觉预算应先扩大当前瞄准方向的命中面，外围线束只负责补足战场，不能把定向武器变成均匀径向烟花。
- 混合路线：保留两套可辨认实体，并通过真实事件产生第三种结果；不得把两张整个人物图或两层全屏染色叠在一起。

## 10. 四类武器的落地示例

| 武器 | 核心关系 | 应长在何处 | 攻击因果重点 |
|---|---|---|---|
| 马克笔 | 改变攻击路径 | 笔在外围近身瞄准；复写/留档墨盒并列装在共用背部打印坞；笔头/身/尾装在真笔上 | 身体保护段 → 笔 → 单一可见激光/墨迹；交点才触发调阅 |
| 保温杯 | 改变战场空间 | 杯体/蒸汽口属于武器；储压或冷凝装置属于人物穿戴/部署件 | 杯口 → 蒸汽扇面；击杀点才产生热浪 |
| 剪刀 | 改变自身位置 | 完整剪刀围绕角色近身；进度与方向指示在前方地面 | 移动蓄能 → 快速位移 → 刃口剪切/刺击 |
| 修正液 | 改变敌人状态 | 瓶体/喷头属于武器；错误标记属于敌人；错误区属于世界 | 喷涂 → 错误层 → 过载 → 扩散或纠错 |

新增武器必须先写清同样四列，再制作素材。

## 11. 运行时数据合同

每个可见武器实体至少声明：

```js
{
  id: "copy-controller",
  visualRole: "route-controller",
  owner: "player",
  socket: "printer-dock-right",
  follows: "player-facing",
  stateSource: "modules.copy",
  attackOrigin: null,
  judgmentPath: null,
  directionFrames: 4,
  zMode: "world-y"
}
```

攻击实体还必须声明或可推导：

- `attackOrigin`
- `aimAngle`
- `judgmentPath / radius / polygon`
- `anticipation / release / impact / residual / fade`
- `source / family / role / intensity`

渲染器不能重新猜测一套独立坐标。

## 12. 素材制作要求

- 先在游戏目标尺寸验证轮廓，再制作大图展示。
- 人物骨架、武器朝向、路线穿戴件、组件和攻击图集分层生产，不使用完整角色插画互相叠加。
- 人物至少覆盖实际移动朝向；瞄准武器至少覆盖八方向或能安全连续旋转的原生资产。
- 穿戴件若只提供一个方向，必须能由运行时旋转且仍保持合理；否则补齐方向帧。
- 动态效果必须提供完整阶段，不能只有一张发光贴图：前摇、释放、命中、残留、消散按机制取舍。
- 视觉资产必须进入真实运行映射；仅预加载、仅出现在说明页或仅存在于文件夹不算实装。

## 13. 验证矩阵

每次武器视觉大改至少检查：

1. 四个人物朝向：上、下、左、右。
2. 八个攻击方向，特别是人物与武器交叉遮挡的方向。
3. 基础、路线 A Lv1—Lv4、路线 B Lv1—Lv4、2+1、2+2、3+1。
4. 无组件，以及每个组件分支安装后。
5. 敌人贴身、近距、中距、最大范围边缘。
6. 移动、站立、目标快速换向、密集敌群和 Boss 体型。
7. 关闭 HUD 后，仍能否指出武器、路线、等级趋势和本次攻击来源。

## 14. 验收清单

- [ ] 每个可见部件都有 owner、socket、follows 和 stateSource。
- [ ] 穿戴件真的和身体发生安装/遮挡关系，而不是孤立漂浮。
- [ ] 只有瞄准武器追随攻击方向。
- [ ] 攻击可沿人物 → 武器 → 特效 → 命中完整追溯。
- [ ] 贴身敌人不会落入非设计性的身体—武器盲区。
- [ ] 可见范围与实际判定一致。
- [ ] 模块、组件和属性变化都长在对应真实实体上。
- [ ] Lv1—Lv3逐级可见，Lv4有独立终局形态。
- [ ] 两条路线颜色和形态不会长期融合成一团光。
- [ ] 角色仍可辨认，但异化装置不显得与人物毫无关系。
- [ ] 视觉在 10 秒内反馈重要 Build 选择。
- [ ] 自动 QA 与玩家视角浏览器矩阵均通过。

## 16. 实机光感三层合同

发光不是生成大图时的装饰，而是必须随正式资产一起落入实机的状态语言。所有后续武器、穿戴件、模块和攻击特效统一按三层制作与验收：

1. **清晰本体层**：深色实体边框、现实原型、安装接口和朝向在关闭发光后仍然成立。不得依赖一团光解释物体是什么。
2. **高对比内核层**：只点亮真正承载状态的结构，例如液窗、输出格栅、压力表、刃口或错误标记；内核必须与模块等级、充能或触发数据同源。
3. **低透明外辉光层**：使用同一内核资产形成受控 bloom，只增强能量感，不扩大判定、不遮住角色和敌人，也不把两条路线融合成一种颜色。

执行规则：

- 禁止对整个人物或整把武器使用全局 `hue-rotate` 代替路线区分。
- 混合路线同时保留两套内核颜色；融合色只在真实交互事件发生的位置和短暂时间内出现。
- Lv0 为熄灯或低亮待机，Lv1—Lv4 的内核亮度与外辉光强度必须单调上升；Lv4 仍需独立结构或攻击事件，不能只靠更亮。
- 外辉光从已批准的透明位图内核提取，不使用脱离实体的 Canvas 几何块或屏幕固定光斑。
- 首次接入先在当前 78px 正式尺度和 64px 压力尺度检查；64px 下至少保留武器类别、路线颜色和主要安装关系。
- 生成图、去底图、实机裁切图、等级光层和运行时映射必须可追溯；只存在于展示图或说明页不算完成。
