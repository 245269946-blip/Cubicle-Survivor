# Demo V1 三武器机制验收矩阵

> 本文只描述当前 `Cubicle-Survivor-demo` 的 Demo V1。`src/v2` 是内部代码目录，不代表另一个产品版本。后续检查不得再引用旧版武器逻辑。

## 当前唯一基线

- 运行入口：`Cubicle-Survivor-demo/index.html`
- 形态定义：`Cubicle-Survivor-demo/src/v2/data/weapon-forms.js`
- 战斗判定：`Cubicle-Survivor-demo/src/v2/combat/systems.js`
- 转正、卡槽、精修、跨部门：`Cubicle-Survivor-demo/src/v2/progression/progression.js`
- 事件签名：`Cubicle-Survivor-demo/src/v2/data/form-signatures.js`
- 自动验收：`node test-runner.js` 与 `node demo-qa.js`

## 当前结论与下一批优化

1. 机制落地与增强合同已经形成可回归基线，不再是“有文案但没有判定”：75 个形态×卡槽组合、15 个转正、15 个精修、15 个资源来源约束、15 个跨部门覆盖以及 6 个跨武器组合均有行为级自动验收。
2. 运行时 VFX 已改成白名单：三张单体实体图与 17 张办公室主题攻击/状态精灵进入运行时；所有贴图的位置、旋转、长宽和实时半径读取战斗判定对象。活动渲染器禁止可见 Canvas 几何图元，旧接触表裁切图与赛博预览条不再进入运行时。
3. 浏览器固定靶场已覆盖 15 个部门形态，并完成 base / promotion / mastery 共 45 个场景的增强前后对照；页面脚本错误为 0。
4. 下一批优先项是音频事件映射、真实玩家盲测与节奏/数值调优，不应在这之前扩武器或新增系统。音频需要分别对应装订、蓄热、释放、破盾、传播、闭合，而不是只按武器播放一套通用音效。

## 回归标准

- 机制不能只产生事件或动画，必须产生目标选择、伤害区、状态、护盾、位移或输入窗口中的至少一项真实判定。
- 增强文案中的数量、范围、时序、代价和状态必须能在运行时对象或事件轨迹中观察到变化。
- `test-runner.js` 必须通过 15 形态、卡槽、转正、跨阶段链路。
- `demo-qa.js` 必须通过机制契约、压力关和三把武器各自 16 关真实战斗路径。
